# Инструкция — доступ iiko для интеграции с KitchenDesk

Для кого: технолог/системный администратор заведения, который
настраивает iiko и может завести отдельного сотрудника. Прочитать и
выполнить шаги 1–5 по порядку.

**Зачем это вообще нужно.** KitchenDesk подключается к вашей iiko, чтобы
подтягивать состав блюд (ТТК) и график смен. Для этого не нужно отдавать
KitchenDesk ваш личный административный логин/пароль от iiko — вместо
этого заводится **отдельный служебный сотрудник** специально под
интеграцию, с правами только на чтение того, что нужно (товары, ТТК,
сотрудники, график). У него не будет доступа к кассе, финансам,
списаниям и вообще ничему, кроме перечисленного ниже.

Права ниже — не предположение из документации iiko, а то, что реально
проверено рабочим подключением.

## 1. Создать сотрудника в iiko

**Сотрудники → Сотрудники → Добавить.**

- Имя — любое понятное, например `API KitchenDesk`.
- Логин и пароль — придумать новые, отдельные, не переиспользовать
  ничьи личные. Именно их в конце нужно будет передать в KitchenDesk.
- Пинкод — можно оставить пустым/по умолчанию, KitchenDesk его не
  использует.

## 2. Создать (или назначить) урезанную должность

**Сотрудники → Должности** → создать новую должность (например,
`API-интеграция`) — или использовать уже существующую урезанную
должность, если такая уже заведена. Назначить эту должность сотруднику
из шага 1.

## 3. Права доступа — включить ровно три

Открыть права доступа этой должности, развернуть дерево прав целиком и
включить **только эти три** (без кассы, без финансов, без списаний):

| Код | Название в дереве прав | Зачем |
|---|---|---|
| `B_VN` | Просмотр номенклатуры | Список товаров/блюд для импорта ТТК |
| `B_PER` | Просмотр личных данных сотрудников | Список сотрудников для сопоставления в графике |
| `B_EN` | Редактирование номенклатурных справочников | Без него запрос графика/справочников падает с ошибкой доступа |

Про `B_EN`: да, звучит странно, что интеграции на чтение нужно право на
«редактирование» — но это подтверждённый практикой факт: без него часть
запросов (в частности связанных с графиком) отдаёт `403 Permission
denied`, с ним всё, включая реальный «Импорт ТТК» и «Импорт графика»,
проходит без ошибок.

**Больше ничего не включать.** Если в дереве рядом видны похожие пункты
«на всякий случай» — не трогать их, должность должна оставаться
максимально урезанной.

Сохранить должность.

## 4. Передать доступ в KitchenDesk

После шагов 1–3 у вас должно быть три значения — передайте их тому, кто
настраивает подключение в KitchenDesk (карточка ресторана → «Подключение
к iiko» → «Изменить»):

- **URL стенда iiko** — тот же адрес, что используется для входа в
  iikoOffice/iikoWeb.
- **Логин** — тот, что создали в шаге 1.
- **Пароль** — тот, что создали в шаге 1.

После ввода в KitchenDesk нажимается «Проверить» — если всё верно,
подключение подтверждается сразу.

## 5. Проверка после подключения

Каждый пункт должен пройти без ошибок:

1. **«Проверить»** в форме подключения — успех.
2. **«Импорт ТТК»** — результат с числом добавленных/обновлённых карт,
   без ошибки доступа.
3. **«Импорт графика»** — результат с числом проставленных дней, без
   ошибки доступа.

Если что-то из этого выдаёт ошибку доступа (`403`/«Permission denied») —
значит для конкретно этого заведения нужно ещё одно право сверх трёх из
шага 3. Открыть дерево прав этой должности, найти строку с указанным в
ошибке кодом (рядом всегда человекочитаемое название), включить
**только её**, повторить проверку. Включать по одному праву за раз, не
охапкой.

## Про лицензию

При создании такого сотрудника обратите внимание, не появляется ли в
самой iiko предупреждение о лимите пользователей/лицензии — на части
тарифов дополнительный сотрудник может занимать платный слот. Если
лимит есть — либо освободить слот, либо уточнить у поддержки iiko,
считается ли служебный API-пользователь отдельным местом на вашем
тарифе.

## Если что-то не сходится

Написать в KitchenDesk с описанием, на каком именно шаге и с какой
именно ошибкой (текст ошибки целиком, не сокращённо) — так решается
быстрее всего.
