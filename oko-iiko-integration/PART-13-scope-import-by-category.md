# Часть 13 — выбор категории (кухня, не бар) при импорте ТТК

## Проблема

`ttk-import` сейчас тянет **все** товары/техкарты из iiko без фильтра по
группе — `getProducts` + `getAssemblyCharts` без учёта, к какой папке
принадлежит блюдо. На тестовом стенде это незаметно, потому что там нет
папок/категорий вообще (см. ограничение теста в `PART-6-category-
import.md`). На **настоящих заведениях** папки есть — и, как выяснилось,
кухня и бар лежат в iiko **вперемешку в общем списке товаров**, разделены
только группой. Значит на реальном заведении `ttk-import` в текущем виде
затянет барные позиции в KitchenDesk вместе с кухонными — не то, что
нужно (KitchenDesk — инструмент кухни).

## Что уже подтверждено (Часть 5/6)

- `GET /api/v2/entities/products/group/list` — рабочий эндпоинт, отдаёт
  список групп/папок.
- У товара есть поле `parent`, ссылающееся на группу.
- Группы могут быть вложенными (группа внутри группы) — реальная
  глубина вложенности не проверена живьём (на demo пусто), нужно
  перепроверять на реальных данных.

Часть 6 использует эту же группу только **косметически** — заполнить
поле «категория» у уже импортированного блюда. Не фильтрует, что вообще
попадает в импорт. Эта часть — про фильтрацию на входе, до импорта, а не
про то, как называется категория после.

## Предлагаемый подход

1. **На стороне connection** — после успешного подключения к iiko,
   подтянуть список групп верхнего уровня (`GET /api/v2/entities/
   products/group/list`, отфильтровать по `parent` пустой/корневой) и
   дать выбрать **одну корневую группу**, которая соответствует «кухне»
   этого заведения (например `Кухня`, у бара будет своя — `Бар`,
   `Напитки` и т.п., её просто не выбираем).
2. Сохранить выбор — новое поле в `iiko_connections`
   (`iiko_kitchen_group_id` или похоже), рядом с уже существующими
   `base_url`/`login`/`password_encrypted`. Не менять существующую
   схему подключения, добавлять аддитивно.
3. **В `ttk-import`** — перед импортом построить карту `group id →
   parent id` из полного списка групп, для каждого товара пройти вверх
   по цепочке `parent` до корня и проверить, совпадает ли корень с
   выбранной кухонной группой. Импортировать только совпавшие товары.
   Товар без группы вообще (`parent` пустой) — **не импортировать по
   умолчанию** (лучше пропустить лишнее, чем случайно затащить барную
   позицию без категории) — но подтвердить это решение с пользователем
   отдельно, не решать за него молча.
4. **Тост после импорта** — уже есть счётчик created/updated/skipped
   (Часть 6 добавляет свой для автозаполненной категории) — сюда же
   добавить, сколько товаров **пропущено, потому что не в кухонной
   группе** — чтобы админ видел, что фильтр реально сработал, а не
   решил, что забыли половину меню.

## Открытые вопросы

1. **Можно ли выбрать несколько групп**, а не одну? Если кухня в iiko
   разбита на несколько верхнеуровневых папок (не одна общая «Кухня», а
   раздельные «Горячий цех»/«Холодный цех»/«Кондитерка» и т.п. на одном
   уровне с «Баром») — тогда нужен мультивыбор, не одна группа. Не знаю,
   как устроено у конкретных заведений — нужно уточнить перед
   реализацией, не гадать на один вариант.
2. **Что делать с товарами без группы** (пункт 3 выше, «не
   импортировать по умолчанию») — устраивает ли это решение, или для
   таких товаров нужен явный отдельный выбор («на всякий случай всё же
   показывать, но отдельным списком для ручного решения»)?
3. **Существующие уже импортированные блюда** — если сейчас (до этой
   части) на каком-то заведении в KitchenDesk уже затянуты и кухонные, и
   барные позиции вперемешку — эта часть ничего не чистит задним числом,
   только фильтрует будущие импорты. Разбор задним числом — отдельная,
   осознанная задача, не автоматически.

## Тестирование

Тот же ограничитель, что и в Части 6: на demo-стенде папок нет — эту
часть **нельзя протестировать полноценно на demo**, только на реальном
заведении с настоящей структурой папок (кухня отдельно от бара). Часть
проверки (что товар без группы не импортируется, что счётчик считается
правильно) можно синтетически проверить и на demo, но главный сценарий
— разделение кухни и бара — только вживую.
