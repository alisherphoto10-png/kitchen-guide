# Часть 7 — создать тестовые данные в iiko через API (группы, товары, ТТК)

Часть 5 проверяла только чтение (GET). Здесь — можно ли **создавать** данные
на demo-стенде через API, и если да, создать тестовый набор для проверки
Части 6 (и заодно закрыть пробелы Части 5 по продажам/сменам/списаниям, если
не сложно).

## Шаг 1 — разведка записи (сделать первой, не пропускать)

Проверить, что вообще доступно на запись в classic REST API iiko на этом
стенде:

- Группы товаров — есть ли способ создать (`POST`/`import` на
  `entities/products/group` или похожий путь).
- Товары/блюда — классический механизм в iiko часто идёт через XML-импорт
  (что-то вроде `POST /resto/api/products/import` или
  `entities/products/import`) — проверить, что реально работает, по какому
  пути, в каком формате тела запроса (XML/JSON).
- ТТК/калькуляции (`assemblyCharts`) — отдельный вопрос, создаются ли они
  тем же импортом или через другой механизм; возможно, что calculation
  привязана к товару и создаётся вместе с ним, а не отдельно — проверить по
  факту, не предполагать заранее.
- Если у стенда есть открытая документация/swagger (например
  `/resto/api/documentation`, `/swagger`, или что-то похожее) — заглянуть
  туда, это быстрее, чем перебирать пути вслепую.

Если запись в принципе недоступна или требует прав, которых нет у текущих
кредов — зафиксировать это в отчёте и остановиться, дальше пользователь
создаст тестовые данные вручную через сам iiko.

## Шаг 2 — если запись доступна, создать тестовый набор

- **3 группы**: «Основные блюда», «Гарниры», «Десерты».
- **~10 товаров с калькуляциями (ТТК)**, распределённых по группам:
  3-4 в «Основные блюда», 3-4 в «Гарниры», 2-3 в «Десерты».
- **1 товар намеренно без группы** (в корне) — нужен как раз для проверки
  пункта 2 из Части 6 (категория должна остаться пустой, импорт не должен
  падать).
- Состав калькуляций — не обязательно кулинарно осмысленный, реалистичные
  веса ингредиентов достаточно (несколько строк состава на каждое блюдо, как
  у уже существующих «картофель отварной» / «Соус Цезарь»).

## Шаг 3 — если не сложно, заодно (необязательно)

Раз уже есть доступ на запись — можно попутно закрыть пробелы из Части 5:
- Провести пару тестовых продаж по любому из созданных блюд.
- Открыть и закрыть кассовую смену на каком-то сотруднике.
- Провести небольшое списание.

Это отдельно от основной задачи (категории) — если усложняет или API для
этого не находится, не тратить на это время, просто отметить в отчёте, что
не делали и почему.

## После создания

Перепрогнать `ttk-import` на ресторане 6 и проверить, что для новых
(реально существующих в iiko) блюд с группами категория действительно
заполняется, а у блюда без группы остаётся пустой — то есть закрыть те самые
пункты 1 и 3 проверки из Части 6, которые раньше нельзя было проверить
живьём из-за пустого стенда.
