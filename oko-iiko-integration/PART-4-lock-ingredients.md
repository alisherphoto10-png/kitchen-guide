# Часть 4 — подтверждённые поля ТТК (Часть 0, по факту) + блокировка
редактирования ингредиентов для iiko-блюд

Добавлено по итогам живого теста в чате 2026-08-11 (после деплоя реального
импорта). Как и остальные файлы в этой папке — план/ТЗ для серверной сессии,
не проверенный мной по коду напрямую (у меня нет доступа к серверу).

## Закрытие пробела «Часть 0» (по факту, через живой тест в UI)

Исходный план просил явную разведку структуры таблицы `ttk` в начале работы
(«Часть 0»). Формального отчёта с полным списком полей так и не появилось, но
по факту пробел частично закрыт живым тестом через сам интерфейс KitchenDesk:

Отредактирована карточка импортированного блюда «картофель отварной»
(restaurant_id=6) — добавлены фото, рецептура (текст «как готовить»),
категория, цех, сохранено. После этого нажата «Импорт ТТК» повторно:

- **Сохранились без изменений:** фото, рецептура, категория, цех.
- **Перезаписался версией из iiko:** состав/ингредиенты (`ingredients`).

Вывод: в таблице `ttk` (или связанной) точно есть отдельные от `ingredients`
поля минимум под фото, рецептуру (инструкцию приготовления), категорию и цех
— именно они и остаются нетронутыми при повторном импорте. Это подтверждено
поведением, а не чтением схемы — если у кого-то будет доступ к
`/root/kitchendesk/backend`, стоит всё равно свериться с реальной DDL/моделью
и явно перечислить точные имена колонок (это по-прежнему открытый пункт).

## Новая задача: заблокировать ручное редактирование `ingredients` для
iiko-блюд

**Проблема:** сейчас ничто не мешает админу вручную поправить состав в
KitchenDesk — правка держится ровно до следующего нажатия «Импорт ТТК», после
чего молча затирается версией из iiko. Это путает: человек правит состав,
видит, что сохранилось, а потом (возможно совсем в другой день, когда кто-то
ещё раз нажмёт импорт) правка бесследно исчезает.

**Решение:** если блюдо привязано к iiko (то есть последний раз пришло/
обновилось через `ttk-import`), поле состава в редакторе ТТК должно быть
**не редактируемым** — с понятным сообщением вместо тихой блокировки.

### Как отличить iiko-блюдо от обычного

Сейчас в БД нет метки «это блюдо из iiko» — сопоставление при импорте идёт по
`(restaurant_id, LOWER(name))`, без сохранения id/флага. Нужно добавить:

```sql
ALTER TABLE ttk ADD COLUMN iiko_managed_at TIMESTAMP;
```

(имя таблицы/колонки — по факту реальной схемы на сервере, `ttk` тут для
примера, как в остальных файлах папки). В `ttk-import` при каждом
created/updated проставлять `iiko_managed_at = now()`. Ручного способа снять
метку в этой задаче не предусмотрено — можно добавить позже, если понадобится
(например кнопка «отвязать от iiko» в самой карточке).

### Бэкенд

- `GET /api/ttk` (и что там ещё отдаёт карточку блюда кухне/админу) — включить
  поле `iikoManaged: boolean` (`iiko_managed_at IS NOT NULL`) в ответ.
- Эндпоинт сохранения карточки ТТК (обычный ручной `PUT`/`PATCH`, не
  iiko-импорт) — если `iikoManaged` true, **игнорировать** переданное значение
  `ingredients` в теле запроса (не молча принимать и не затирать), даже если
  фронтенд его почему-то прислал — то есть защита должна быть и на бэкенде, не
  только в UI (на случай прямого запроса к API в обход формы).

### Фронтенд

В редакторе карточки ТТК — если `iikoManaged`:
- Поле состава/ингредиентов — `disabled`/`readonly`.
- Рядом (или вместо поля) — текст-предупреждение, по смыслу как обсуждали:
  **«Ингредиенты этого блюда синхронизируются с iiko — редактировать их в
  KitchenDesk нельзя. Изменить состав может администратор iiko вашего
  заведения, в самой системе iiko.»**
  (точную формулировку можно поправить по месту, смысл — состав не
  редактируется здесь, редактируется в iiko).
- Остальные поля карточки (фото, рецептура, категория, цех и что там ещё
  есть) — редактируются как обычно, без ограничений.

### Проверка

1. Открыть карточку iiko-блюда (например «картофель отварной» на ресторане
   6) — поле состава недоступно для редактирования, есть предупреждение.
2. Прямой запрос к API на сохранение с изменённым `ingredients` для такого
   блюда — состав не меняется (бэкенд игнорирует).
3. Остальные поля (фото/рецептура/категория/цех) редактируются и сохраняются
   как раньше — без регрессии.
4. Обычное (не-iiko) блюдо, созданное вручную — редактируется полностью, без
   ограничений (флаг `iikoManaged` не мешает тем, кого не касается).
5. После повторного «Импорт ТТК» — состав по-прежнему обновляется версией из
   iiko, как и раньше; это ожидаемо, блокировка касается только ручного
   редактирования человеком, не самого механизма импорта.
