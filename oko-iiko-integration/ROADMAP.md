# OKO ↔ iiko — дорожная карта (по состоянию на 2026-08-12)

Сводка по всем частям, разбросанным по файлам в этой папке — что реально
сделано и проверено, что только специфицировано, что только разведано, и
что осознанно отложено. Собрано по истории переписки и коммитам веток
`claude/oko-iiko-integration` и `claude/oko-presentation-assets`.

## ✅ Сделано и проверено вживую

- **Подключение к iiko** — таблица `iiko_connections` (пароль зашифрован
  AES-256-GCM, не отдаётся с бэкенда), CRUD только для суперадмина (403
  остальным), тест подключения (404 на пустое), удаление — все проверены
  через публичный домен.
- **`src/services/iiko.js`** — `authenticate`, `getProducts`,
  `getAssemblyCharts`, `getMeasureUnits`, `getEmployees`, `getSchedule`,
  `getEmployeeRoles`.
- **Два бага пофикшены**: обрезание `#` в `.env` через `dotenv`; выбор
  актуальной версии ТТК по `dateFrom`/`dateTo`.
- **Реальный импорт (вариант А)**: `ttk-import` (идемпотентно, состав →
  текст в `ingredients`), `schedule-import` (сопоставление сотрудников по
  имени, `is_working=true`, несопоставленные — в ответе, не теряются).
- **Фронтенд** — `IikoCard` в панели суперадмина: подключение/тест/
  отключение + кнопки импорта с тост-сводкой.
- **Часть 4 — блокировка состава для iiko-блюд**: колонка
  `iiko_managed_at`, флаг `iikoManaged` во всех read-эндпоинтах, бэкенд
  игнорирует присланный `ingredients` для таких блюд при ручном `PUT`,
  фронтенд показывает не редактируемое поле с объясняющим текстом. Фото/
  категория/цех/рецептура остаются свободно редактируемыми и не трогаются
  повторным импортом — подтверждено живым тестом (правка карточки → повторный
  импорт → всё кроме состава осталось как было).

## 🔍 Только разведано (решение по реализации не принято)

**Часть 5 — что ещё есть в iiko API:**

| Что | Статус |
|---|---|
| Группы/категории товаров | Механизм подтверждён, живого примера нет (demo пустой) |
| Стоп-лист | Не найдено ни по одному опробованному пути |
| Остатки на складе | Подтверждено, есть живой непустой пример |
| Аллергены/модификаторы | Поле в схеме есть, везде пустое на demo |
| Кассовые смены (открытие/закрытие) | Эндпоинт есть, 0 смен на demo — не проверено, содержит ли данные по сотруднику |
| Себестоимость/прайм-кост | **Готовый отчёт через OLAP** — не нужно считать самим по брутто/нетто. 0 продаж на demo, живого примера нет |
| Списания | Механизм через OLAP TRANSACTIONS подтверждён, живой пример — но это была накладная, не списание |
| Отчёты по продажам | Эндпоинт есть, 0 продаж на demo |

«План vs факт» смены (макет обсуждали отдельно) технически не проверено —
упирается в то же самое: 0 кассовых смен на demo, нельзя подтвердить, что
там вообще есть привязка к конкретному сотруднику.

## ⏸️ Осознанно отложено

- **TLS** (`rejectUnauthorized: false`) — не блокер для demo, но нужно
  вернуться перед подключением боевых заведений.
- **Вариант Б** (структурные брутто/нетто/% потерь в ТТК, время+должность в
  графике) — только макеты, реализация не начата. С учётом находки по
  себестоимости из Части 5 (готовый отчёт в iiko) вариант Б может
  понадобиться меньше, чем думали — часть его ценности (расчёт
  себестоимости) уже закрывается без него.
- **Кнопка «отвязать от iiko»** — прямо исключена из Части 4, можно
  добавить позже, если понадобится.
- **Ретро-простановка `iiko_managed_at`** на ранее импортированные блюда —
  не делали, само проставится при следующем импорте на каждом ресторане.
