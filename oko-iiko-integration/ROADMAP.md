## ✅ Сделано и проверено вживую

**Базовая интеграция (до Части 8):**
- Подключение к iiko — таблица `iiko_connections` (пароль зашифрован
  AES-256-GCM), CRUD только для суперадмина, тест подключения, удаление.
- `src/services/iiko.js` — `authenticate`, `getProducts`,
  `getAssemblyCharts`, `getMeasureUnits`, `getEmployees`, `getSchedule`,
  `getEmployeeRoles`.
- Два бага пофикшены: обрезание `#` в `.env`; выбор актуальной версии ТТК.
- Реальный импорт (вариант А): `ttk-import` (идемпотентно), `schedule-import`
  (сопоставление по имени, `is_working=true`).
- `IikoCard` в панели суперадмина — подключение/тест/отключение + импорт
  с тост-сводкой.
- **Часть 4** — блокировка состава для iiko-блюд (`iiko_managed_at`,
  флаг `iikoManaged`, не редактируется вручную), фото/категория/цех
  остаются свободными — подтверждено живым тестом.

**Урезанный доступ и график со временем (Части 8–10):**
- **Часть 8/9 — урезанный API-пользователь.** Финальная формула прав:
  `B_VN` + `B_PER` + `B_EN` (последний — «редактирование номенклатурных
  справочников», неочевидно, но подтверждено живьём). Проверено и на
  demo-стенде, и **на реальном заведении** — интеграция реально работает.
- **Инструкция для технолога** (`GUIDE-restricted-iiko-user.md`) —
  готова, есть в трёх видах: markdown в репозитории, HTML-страница
  (можно скинуть ссылкой), PDF-файл. Терминология сверена с живым
  интерфейсом iiko («Должности», не «Роли»).
- **Часть 10 — время смены + коллеги по цеху.** Реализовано и задеплоено:
  БД — аддитивные поля (`shift_start`/`shift_end`/`role_label`) рядом с
  `is_working`; бэкенд — `GET /api/schedule/today` и
  `GET /api/schedule/colleagues?date=`, роль/грейд нигде не отдаётся
  наружу; фронтенд — карточка смены на «Главной» (три состояния:
  заглушка/выходной/время, тап открывает неделю), блок коллег на
  «Профиле». **Подтверждено пользователем на реальном графике реального
  заведения — работает.**
- **Часть 13 — фильтр импорта ТТК по категории (кухня, не бар).**
  Реализовано и задеплоено полностью: дерево групп из iiko (`GET .../
  products/group/list`) с чекбоксами в `IikoCard`, выбор сохраняется на
  подключении (`iiko_kitchen_group_ids`), и `ttk-import`, и `ttk-preview`
  импортируют/показывают только совпавшие по `parent` блюда + счётчик
  `skipped_group` (превью без фильтра, только пока категории ни разу не
  сохранялись). Сборка и миграция подтверждены живьём. **Реальная
  проверка на настоящем дереве «Кухня»/«Бар» ещё не проведена** —
  demo-стенд без папок вообще, там тест синтетический (см.
  `REPORT-2026-08-17-part13-implemented.md`).

## ⏸️ Приостановлено (не закрыто окончательно)

- **Часть 12 — опоздание и факт открытия смены.** Путь через
  KitchenDesk-механизм (кнопка/авто-фиксация) закрыт как ненадёжный —
  не все сотрудники открывают смену через приложение предсказуемо. Путь
  через iiko переоткрыт условно: пользователь утверждает, что у
  конкретного заведения есть свой механизм для поваров — нужна живая
  проверка (готов скрипт `backend/probe-personal-shifts.sh`), не
  проводилась. **Решено пока не гнаться дальше — делать вручную,
  вернуться на практике**, когда будет понятно, что и как. Ничего не
  реализовано, ничего не заблокировано — просто пауза.
