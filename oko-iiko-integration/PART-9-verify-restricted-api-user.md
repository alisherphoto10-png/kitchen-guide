> авторизация урезанными кредами работает; как минимум один метод дал
> `403 Permission denied: B_EN...` — рекомендация `B_VN`+`B_PER` из Части 8
> подтверждена неполной, нужно ещё одно право. Полный прогон чек-листа

Часть 8, п.8.2 разведала (по документации, не проверено вживую), что iiko
поддерживает ограниченную должность (`B_VN` + `B_PER`, без кассы/финансов)
специально под API-интеграцию. Пользователь **реально создал такого
сотрудника** в iiko на demo-стенде. Логин/пароль переданы отдельно, вне
этого файла (не хранить их в git — см. инструкцию к этой части).

## Что проверить

1. **Сначала напрямую к iiko**, в обход KitchenDesk — авторизоваться этими
   кредами через `authenticate()` (`src/services/iiko.js`), убедиться, что
   токен реально выдаётся.
2. С этим токеном вызвать по очереди то, что реально нужно интеграции:
   `getProducts`, `getAssemblyCharts`, `getEmployees`, `getSchedule`,
   `getEmployeeRoles`, `getMeasureUnits` — по каждому зафиксировать: работает
   как обычно, или где-то не хватает прав (`403`/пустой ответ там, где с
   полным админским доступом было что-то).
3. **Затем через сам KitchenDesk** — сменить подключение ресторана 6 (или
   тестового) с текущих `user`/`user#test` на эти новые креды через форму
   «Подключение к iiko» (кнопка «Изменить»), нажать «Проверить».
4. Прогнать реальный **«Импорт ТТК»** и **«Импорт графика»** с этим
   подключением — сравнить результат (created/updated, число сотрудников
   сопоставлено) с тем, что было раньше при полном доступе — должно
   совпадать, раз данных с тех пор в iiko не убавилось.

## Особый интерес — лицензионный слот

Ранее в чате обсуждали (но не проверяли вживую): занимает ли новый
API-логин слот лицензии iiko. Раз сотрудник уже реально создан —
**зафиксировать по факту**, не появилось ли при создании/использовании
предупреждений о лимите пользователей/лицензии (в самой iiko при создании,
или ошибок при авторизации, похожих на «превышен лимит»). Не гарантирован
ответ на этот вопрос только тестом на одном demo-стенде (там может не быть
лимита вообще), но если что-то всплывёт — зафиксировать.

## Проверка

1. Прямая авторизация к iiko этими кредами — успешна.
2. Все нужные интеграции методы API отрабатывают (список в п.2 выше) — без
   `403`/урезанных ответов.
3. Подключение в KitchenDesk переключено, «Проверить» — `{"ok": true}`.
4. «Импорт ТТК»/«Импорт графика» — реально отработали, результат
   сопоставим с прошлыми прогонами на полном доступе.
5. Замечено ли что-то про лицензионный слот — да/нет, что именно.

## Отчёт

По каждому пункту — что подтвердилось. Если что-то из интеграции **не**
сработало с урезанными правами — явно назвать, каких прав не хватило,
чтобы понять, точна ли была рекомендация `B_VN`+`B_PER` из Части 8, или
нужно расширять список прав.
