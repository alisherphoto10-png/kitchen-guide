# Отчёт — Часть 9: живая проверка урезанного API-пользователя

Статус: **право найдено и подтверждено, основной прогон пройден**.
Остаётся добить пару пунктов чек-листа (см. «Что ещё не закрыто» ниже) —
это уже механическая доработка, не разведка.

## Формула прав — итог

```
B_VN + B_PER + B_EN
```

- `B_VN` — просмотр номенклатуры (было в рекомендации Части 8).
- `B_PER` — просмотр личных данных сотрудников (было в рекомендации
  Части 8).
- `B_EN` — **редактирование номенклатурных справочников** — новое,
  найденное в этой части. Без него `getEmployeeRoles`/`getMeasureUnits`
  (или что там конкретно вызывается при импорте ТТК) отдавало `403
  Permission denied: B_EN...`.

Название права подтверждено вручную, глазами, в дереве прав iiko (не
догадка из документации). Это закрывает открытый вопрос из предыдущей
версии этого отчёта — рабочая гипотеза (что `B_EN...` относится к более
широкому классу «сущностей/справочников», отдельному от `B_PER`/`B_VN`)
подтвердилась почти точно: это тоже номенклатурные справочники, просто
**на редактирование**, а не только просмотр — то есть iiko для этого
вызова classic REST API требует edit-права, а не read-only. Стоит иметь в
виду на будущее: не все «read»-операции интеграции в iiko гарантированно
покрываются одними «просмотровыми» правами.

## Что подтвердилось

1. Прямая авторизация к iiko урезанными кредами (`B_VN`+`B_PER`) —
   работает, подтверждено ещё в прошлой версии отчёта.
2. `403 Permission denied: B_EN...` — воспроизведено, локализовано, право
   добавлено вручную через дерево прав в iiko (не весь раздел целиком —
   именно этот один пункт).
3. **Реальный «Импорт ТТК» после добавления права — прошёл без ошибок.**
   Это прямое живое подтверждение, что добавленного набора прав достаточно
   для этого сценария целиком (не только для отдельного вызова API в
   изоляции).

## Что ещё не закрыто

- Отдельного целенаправленного прогона всех методов по списку
  (`getProducts`, `getAssemblyCharts`, `getEmployees`, `getSchedule`,
  `getEmployeeRoles`, `getMeasureUnits`) не было — был прогон реального
  сценария «Импорт ТТК» целиком, который, по всей видимости, использует
  большинство из них (иначе `403` не всплыл бы). `getSchedule` в этот
  сценарий не входит.
- **«Импорт графика»** отдельно не проверялся — это единственный сценарий,
  который целенаправленно упирается в `getSchedule`/`getEmployees`, и его
  стоит прогнать отдельно, а не считать закрытым по аналогии с ТТК.
- Явного подтверждения, что подключение ресторана 6 в KitchenDesk
  переключено именно через форму «Подключение к iiko» (кнопка «Изменить»
  → «Проверить») — нет; проверка импорта ТТК могла идти либо через это
  подключение, либо отдельным прямым тестом. Если через форму — можно
  считать пункт 3 из исходного чек-листа Части 9 закрытым, но это стоит
  явно подтвердить.
- Наблюдение по лицензионному слоту — по-прежнему ничего тревожного не
  всплывало на всех шагах (создание сотрудника, авторизация, добавление
  права, реальный импорт), но целенаправленно не проверялось — остаётся
  открытым как есть.

## Итог

Часть 8 п.8.2 подтверждена **полностью верной** по существу: iiko
поддерживает урезанную должность под API-интеграцию, но точная формула прав
— `B_VN` + `B_PER` + `B_EN`, а не только первые два. Рекомендацию/
инструкцию для технолога (если и когда она будет оформляться отдельным
документом по итогам 8.2) — обновить именно этой тройкой прав.
