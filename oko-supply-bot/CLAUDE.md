# Проект: Заказ поставщикам + автоответчик (личный Telegram-userbot)

Этот файл — точка входа для Claude Code. Прочитай его целиком перед тем, как начинать
писать код: здесь весь контекст "что, как и зачем", чтобы не переспрашивать заново.

## Зачем это вообще нужно

Алишер — шеф-повар (OKO Gastrobar) и по совместительству разработчик своих Telegram-ботов
(на Google Apps Script + Telegram Bot API). Сейчас две смежные задачи, которые логично
делать вместе, потому что у них общий технический фундамент:

1. **Автоответчик** — когда Алишер занят (на кухне), на входящие личные сообщения
   должен автоматически уходить ответ вроде "Алишер сейчас занят, ответит как освободится".
   Без ИИ-подстановки, просто фиксированный текст. Когда Алишер сам заходит в сеть — видит
   непрочитанные и отвечает как обычно.
2. **Заказ поставщикам в один тап** — Алишер тапает нужные продукты (рыба, мясо, креветки
   и т.д.) из общего каталога, система сама находит, у какого поставщика есть каждый товар,
   группирует заказ по поставщикам и отправляет каждому готовое сообщение с датой поставки,
   количеством и (опционально) комментарием и фото товара.

## Почему это не обычный Telegram-бот

Ключевое требование: сообщения (и автоответ, и заказы поставщикам) должны уходить
**от личного Telegram-аккаунта Алишера**, а не от бота с @username. Поставщик должен видеть
переписку так, будто Алишер написал сам — не бот.

Обычный Bot API (которым уже пользуется Алишер в других проектах) на это не способен —
это ограничение самого Telegram. Значит нужен **userbot**: MTProto-клиент (библиотека
**Telethon** на Python), который логинится под номером телефона Алишера и работает как
обычный клиент Telegram, только программно.

## Как всё это устроено (архитектура)

```
┌─────────────────────┐        ┌──────────────────────┐
│   WebApp (форма)     │  ───▶  │   Backend / API       │
│  тап по товарам,      │        │  группирует по         │
│  количество, дата,    │        │  поставщику, хранит    │
│  комментарий, фото     │        │  каталог               │
└─────────────────────┘        └──────────┬───────────┘
                                            │
                                            ▼
                                ┌──────────────────────┐
                                │  Userbot (Telethon)    │
                                │  логинится под номером  │
                                │  Алишера, шлёт заказ    │
                                │  в чат поставщика       │
                                │  + отвечает автоответом │
                                └──────────────────────┘
```

- **Каталог** (товары + поставщики) — источник правды. У Алишера уже есть централизованный
  backend (Node.js/Python, один ключ Anthropic API, см. существующую инфраструктуру ботов) —
  этот модуль логично подключить туда же, а не городить отдельный сервис с нуля.
- **WebApp** — Telegram WebApp-форма (как и в других проектах Алишера), открывается по
  персистентной кнопке, а не по одноразовой ссылке.
- **Userbot** — отдельный процесс на Telethon (не Bot API!), с session-файлом, требует
  однократный логин по номеру телефона + код подтверждения.

## Прототип интерфейса (уже готов, служит референсом UX)

Есть кликабельный HTML-прототип всего пользовательского пути — `order-prototype.html`
(положи его в `webapp/reference/` при инициализации репозитория). Он не про код бэкенда,
а про то, как должен ощущаться флоу. Экраны:

1. **Список товаров** — поиск + тап → степпер количества. Значок ⚙️ ведёт в управление
   каталогом.
2. **Проверка заказа** — сгруппировано по поставщикам. У каждого поставщика:
   - список позиций с количеством (редактируется тут же, +/−)
   - **дата поставки** — своя для каждого поставщика (не одна на весь заказ)
   - необязательный комментарий к заказу
   - превью финального текста сообщения
3. **Подтверждение отправки** — по одной галочке на каждого поставщика.
4. **Управление каталогом** — две вкладки: «Товары» и «Поставщики».
   - **Карточка товара**: фото, название, единица измерения, поставщик (select).
   - **Карточка поставщика**: название, телефон, Telegram (раздельные поля), и список
     товаров этого поставщика — тап по товару открывает ту же карточку товара, что и в
     общем списке (это один и тот же объект в каталоге, не копия).

## Модель данных (минимум для MVP)

**Товар**
- `name` — название
- `unit` — единица измерения (кг / шт / л)
- `supplier` — ссылка на поставщика (по имени или id)
- `photo` — фото товара (опционально)

**Поставщик**
- `name`
- `phone` — номер телефона (опционально)
- `telegram` — @username (опционально)
- `chat_id` — Telegram chat_id личного чата с этим поставщиком (заполняется по мере
  появления реальных чатов — см. ниже)

**Заказ / позиция заказа**
- товар, количество, поставщик (выводится автоматически из товара)
- `delivery_date` — своя дата на каждого поставщика
- `comment` — опционально
- статус отправки

## Текущий статус по данным

- Реальный список поставщиков и что у кого заказывается — уже есть (26 поставщиков,
  с телефонами/Telegram-контактами кто где указан), был перенесён в Google Sheets
  (`Поставщики_и_товары.xlsx`, два листа: "Поставщики" и "Товары по позициям").
- **Чатов с поставщиками в Telegram пока нет** — Алишер только начинает эту часть.
  План: сперва протестировать механику на группе + паре уже существующих личных чатов
  (вручную прописав их chat_id вместо настоящих поставщиков), и только когда логика
  работает стабильно — переходить на реальных поставщиков.

## С чего начать писать код

1. Поднять Telethon-сессию (однократный логин под номером Алишера), проверить, что можно
   программно отправить сообщение в тестовый чат.
2. Собрать минимальный каталог (можно начать с JSON/таблицы, синхронизацию с Google Sheets
   добавить позже) — товар → поставщик → chat_id.
3. Реализовать группировку "тапнутые товары → по поставщикам" и рендер шаблона сообщения
   (по образцу текста из прототипа: дата, список позиций, комментарий).
4. Отправку через Telethon в соответствующий тестовый chat_id.
5. Отдельно, той же сессией Telethon: слушатель входящих личных сообщений + переключатель
   "занят/свободен" (например, командой в Избранное) для автоответчика.
6. Когда механика отправки заказов обкатана на тестовых чатах — заменить тестовые chat_id
   на реальные по мере появления чатов с поставщиками.

## Что явно НЕ нужно (пока)

- Никакого ИИ-подбора текста для автоответчика — фиксированная фраза.
- Не обобщать на другие рестораны/venues — это личный инструмент Алишера.
- Не использовать обычный Telegram Bot API для отправки — только userbot (Telethon),
  иначе поставщик увидит бота, а не личный аккаунт.
