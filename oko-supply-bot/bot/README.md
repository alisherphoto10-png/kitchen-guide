# Userbot (Telethon)

Telethon-часть проекта: userbot от личного аккаунта Алишера — отправка заказов
поставщикам + автоответчик на личные сообщения. Не Bot API — иначе поставщик
увидит бота, а не личный аккаунт (см. корневой `CLAUDE.md`).

## Установка

```
pip install -r requirements.txt
cp .env.example .env
```

В `.env`:
- `TG_API_ID` / `TG_API_HASH` — получить на https://my.telegram.org
  («API development tools», создать приложение)
- `TG_PHONE` — номер телефона Алишера

## Первый запуск — логин (сделать один раз, на той машине, где бот будет жить)

```
python send_order.py
```

При первом запуске любого скрипта Telethon спросит в терминале код
подтверждения (придёт в Telegram) и, если включена, облачный пароль.
После этого рядом появится файл `oko_supply_bot.session` — он и есть
авторизация, повторно код вводить не нужно. **В git не коммитить**
(уже в `.gitignore`).

## Файлы

- `client.py` — фабрика `TelegramClient` из `.env`
- `catalog.py` — загрузка `../data/catalog.json`, поиск товара/поставщика
- `message.py` — группировка позиций по поставщику + рендер текста сообщения
- `send_order.py` — тестовая отправка заказа (пока список позиций захардкожен
  в `TEST_ORDER`, дальше сюда будет приходить то, что натапали в webapp)
- `autoresponder.py` — слушатель личных сообщений + переключатель занят/свободен
  командами `/busy` и `/free` в Избранном (Saved Messages)

## Тестовые chat_id

Прежде чем слать реальным поставщикам — прописать `chat_id` тестовых чатов
(группа + пара личных чатов) в `../data/catalog.json`, у нужных поставщиков.
Узнать `chat_id` можно, например, вызвав `client.get_dialogs()` и напечатав
`id` нужного диалога — отдельного скрипта для этого пока нет, добавим при
необходимости.

## Запуск автоответчика

```
python autoresponder.py
```

Дальше в Избранном пишешь `/busy` — автоответчик включается, `/free` —
выключается. Процесс должен работать постоянно (на сервере, через pm2/systemd
или аналог) — в этом MVP запуска-как-сервиса ещё нет.
