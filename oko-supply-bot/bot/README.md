# Userbot (Telethon)

Telethon-часть проекта: userbot от личного аккаунта Алишера — отправка заказов
поставщикам + автоответчик на личные сообщения. Не Bot API — иначе поставщик
увидит бота, а не личный аккаунт (см. корневой `CLAUDE.md`).

## Установка

```
pip install -r requirements.txt
cp .env.example .env
```

В `.env`:
- `TG_API_ID` / `TG_API_HASH` — получить на https://my.telegram.org
  («API development tools», создать приложение)
- `TG_PHONE` — номер телефона Алишера

## Первый запуск — логин (сделать один раз, на той машине, где бот будет жить)

```
python send_order.py
```

При первом запуске любого скрипта Telethon спросит в терминале код
подтверждения (придёт в Telegram) и, если включена, облачный пароль.
После этого рядом появится файл `oko_supply_bot.session` — он и есть
авторизация, повторно код вводить не нужно. **В git не коммитить**
(уже в `.gitignore`).

## Файлы

- `client.py` — фабрика `TelegramClient` из `.env`
- `catalog.py` — загрузка `../data/catalog.json`, поиск товара/поставщика
- `message.py` — группировка позиций по поставщику + рендер текста сообщения
- `send_order.py` — тестовая отправка заказа из терминала (список позиций
  захардкожен в `TEST_ORDER`, для быстрой проверки без webapp)
- `autoresponder.py` — слушатель личных сообщений + переключатель занят/свободен
  командами `/busy` и `/free` в Избранном (Saved Messages)
- `webapp_server.py` — веб-сервер формы заказа + управления каталогом (см. ниже)
- `list_chats.py` — печатает последние диалоги с их `chat_id`

## Тестовые/реальные chat_id

Прежде чем слать поставщику — нужен его `chat_id`. Узнать:

```
python list_chats.py
```

Выведет последние диалоги (личные чаты, группы) с их `id`. Вписать его можно
либо прямо в `../data/catalog.json`, либо через саму форму — ⚙️ в шапке →
вкладка «Поставщики» → карточка поставщика → поле «Chat ID».

## Форма заказа (webapp)

```
python webapp_server.py
```

Поднимает сервер на порту `WEBAPP_PORT` из `.env` (по умолчанию `8081`) —
отдаёт `../webapp/order.html` и обслуживает `/api/catalog` и `/api/order`.
При старте логинится тем же Telethon-клиентом (session уже есть — новый вход
не потребуется) и держит его открытым, пока сервер работает.

Открывать по прямой ссылке на телефоне (`http://<сервер>:8081/`), без
отдельного Telegram-бота — сообщения поставщикам всё равно уходят через
userbot, кнопка тут ни при чём. Чтобы открывалось не только из локальной
сети — нужен reverse-proxy (nginx) с проксированием на этот порт, как для
остальных фронтендов на сервере; сам сервер слушает обычный HTTP без TLS.

Шестерёнка ⚙️ в шапке формы открывает управление каталогом — добавление,
редактирование и удаление товаров и поставщиков (включая `chat_id`), пишет
прямо в `data/catalog.json` через `/api/catalog/*`.

## Запуск автоответчика

```
python autoresponder.py
```

Дальше в Избранном пишешь `/busy` — автоответчик включается, `/free` —
выключается. Процесс должен работать постоянно (на сервере, через pm2/systemd
или аналог) — в этом MVP запуска-как-сервиса ещё нет.
