# Часть 9 — «Добавлено» не сбрасывается между разными банкетами

## Симптом (от пользователя)

1. Создал банкет 1, добавил блюдо (например «Баклажан с Тахини») — кнопка
   стала «✓ Добавлено», реально добавилось.
2. Создал банкет 2 (второй, отдельный), открыл «Добавить блюдо», то же
   самое блюдо в списке **сразу показывает «✓ Добавлено»**, хотя в банкет
   2 его ещё не добавляли.
3. По факту — блюда в банкете 2 нет (реального добавления не произошло),
   просто кнопка врёт.

## Вероятная причина (проверить, не считать готовым выводом)

Состояние «добавлено» у позиции в модалке выбора блюд, похоже, не
сбрасывается/не пересчитывается при смене выбранного банкета — либо:
- Хранится в локальном state компонента, который не размонтируется между
  открытиями модалки для разных банкетов (тот самый оптимистичный
  локальный флаг из Части 4.4 — «мгновенная локальная отметка сразу после
  успешного добавления» — вероятно, не привязан к `banquet_id`, просто
  держится в памяти компонента).
- Или сверяется с реальными позициями банкета (`banquetDetail.items`), но
  подтягивается не того банкета (закешированный старый ответ, не
  актуальный на смену `banquet_id`).

## Что нужно сделать

1. Воспроизвести ровно по шагам симптома выше — подтвердить.
2. Найти, где хранится флаг «добавлено» у позиции в модалке — привязан ли
   он к `banquet_id`, или общий на все банкеты.
3. Починить так, чтобы состояние «добавлено» **всегда** сверялось именно с
   текущим открытым банкетом — при смене банкета (или просто при каждом
   открытии модалки) состояние должно браться заново из реальных данных
   этого банкета, а не переноситься из предыдущего сеанса работы с
   модалкой.

## Проверка

1. Банкет 1 → добавить блюдо X → закрыть модалку.
2. Переключиться на банкет 2 (другой, реально отдельный) → открыть «Добавить
   блюдо» → блюдо X показывает обычную кнопку «Добавить», не «Добавлено».
3. Добавить блюдо X в банкет 2 → реально появляется в его меню банкета (не
   только кнопка меняется — проверить список позиций банкета 2 после
   закрытия модалки).
4. Вернуться на банкет 1 → блюдо X там по-прежнему показано как
   добавленное (проверка, что фикс не сломал обратную сторону — состояние
   не должно тоже неправильно сброситься там, где оно верное).

## Отчёт

**Причина** — подтвердился первый из двух вариантов в разделе «Вероятная
причина» выше, второй («сверяется с реальными позициями банкета, но не
того банкета») не подтвердился и был отдельно проверен и исключён (см.
API-проверку ниже — `banquetDetail.items` всегда корректно относится к
своему `banquet_id`, кэш тут не при чём).

Флаг `justAdded` (Часть 4.4, «мгновенная локальная отметка сразу после
успешного добавления») — обычный `useState<Set<number>>` в теле
компонента `Banquet.tsx`. Компонент не размонтируется при переключении
между банкетами (меняется только `selected`, экран тот же), поэтому `Set`
жил в памяти неограниченно и просто накапливал id блюд по всем банкетам,
в которые их когда-либо добавляли за сеанс работы со страницей.
`addedTtkIds` собирался как объединение `banquetDetail.items` (правильно
привязан к `banquet_id` через `queryKey: ['banquet', selected?.id]`) и
этого самого `justAdded` — вторая часть подмешивала чужие id, отсюда
ложное «✓ Добавлено» в банкете 2 для блюда, реально добавленного только в
банкет 1.

**Фикс** — один `useEffect`, сбрасывающий `justAdded` в пустой `Set` при
каждой смене `selected?.id`:

```tsx
useEffect(() => { setJustAdded(new Set()) }, [selected?.id])
```

(`Banquet.tsx`, рядом с объявлением `justAdded`). Задеплоено — бандл
`/home/kitchendesk/frontend` пересобран и обновлён.

**Проверка** — в этой сессии не было подключённого браузера (Claude in
Chrome не настроен), поэтому реальный клик по кнопке в модалке не
выполнялся; проверено прямыми запросами к живому API
(`kitchendesk` backend, `POST/GET/DELETE /api/banquets`) на двух отдельных
тестовых банкетах (созданы и после проверки удалены, id 22 и 23,
production-банкеты 9–21 не затронуты):

1. Банкет A (id 22) → добавлено блюдо «Баклажан с Тахини и помидорами»
   (ttk #4, 2 порции) → `GET /api/banquets/22` подтверждает позицию.
2. `GET /api/banquets/23` (банкет B, до добавления) → `items: []` — то же
   блюдо в банкете B не числится, хотя уже добавлено в A. Это подтверждает,
   что серверная половина `addedTtkIds` (`banquetDetail.items`) всегда была
   изолирована по `banquet_id` — она не была источником утечки, как и
   предполагалось.
3. В банкет B (id 23) добавлено то же блюдо (ttk #4, 3 порции) →
   `GET /api/banquets/23` подтверждает реальное добавление (не только
   визуальный флаг) отдельной позицией с banquet_id=23.
4. `GET /api/banquets/22` после этого → блюдо по-прежнему там, с исходными
   2 порциями — обратная сторона не сломалась, данные банкета A не задеты
   добавлением в банкет B.

Это закрывает серверную/данные-часть проверки 1–4 из чек-листа выше.
Сам репортед-симптом (кнопка `justAdded`) — чисто клиентское React-состояние,
не наблюдаемое через API; его корректность подтверждена чтением фикса
(`useEffect` с зависимостью `[selected?.id]` — стандартный React-паттерн
сброса state при смене id) и тем, что до фикса `justAdded` не имел вообще
никакой зависимости для сброса. Рекомендуется разовый ручной клик в
браузере (создать банкет 1 → добавить блюдо → создать банкет 2 → открыть
«Добавить блюдо» → убедиться, что кнопка обычная, не «Добавлено») как
финальное визуальное подтверждение, когда будет доступен браузер.
