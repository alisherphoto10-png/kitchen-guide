# Печать чек-листа смены + завершение сканом QR — план (ещё не реализовано)

Это ТЗ, не код. Записано по итогам обсуждения с пользователем — реализация
будет позже, отдельной сессией с доступом к серверу (в частности, к
главному бэкенду KitchenDesk, `kitchen2026.chefplan.ru`, исходники которого
в этом репозитории не лежат — см. "Где что лежит" ниже).

## Идея в одном абзаце

В экране "Чек-лист" (Telegram mini-app, `Checklist.tsx`) рядом с кнопкой
"🏁 Завершить смену" появляется кнопка "🖨️ Печать". По нажатию печатается
бумажный чек-лист (список позиций + текущая отметка выполнено/нет) с QR-кодом
внизу. Скан QR (любой камерой телефона, без захода в приложение) —
**второй, равнозначный** способ завершить смену: делает то же самое, что и
кнопка "Завершить смену" в приложении (помечает смену завершённой,
отправляет тот же отчёт в Telegram). Кнопка в приложении при этом
продолжает работать как раньше, никуда не убирается — это два параллельных
способа одного действия, не замена друг друга.

## Где что лежит (важно, чтобы не потерять контекст)

- **Кнопка, экран чек-листа, вызов API** — `Checklist.tsx` +
  `services/api.ts` в фронтенде главного приложения. В `kitchen-guide` есть
  только устаревший снэпшот этого фронтенда
  (`oko-kitchen-frontend.tar.gz`) для справки по структуре — актуальный
  исходник живёт в другом месте, фронтенд-часть этого плана нужно будет
  сверять с реальным кодом на сервере/в его репозитории.
- **`/api/checklist`, `/api/shift/finish`, отправка отчёта в Telegram** —
  главный бэкенд KitchenDesk, `kitchen2026.chefplan.ru`. На сервере это
  `/root/kitchendesk/backend`, роуты подключены в `src/index.js:26-27`
  (`app.use('/api/checklist', require('./api/checklist'))`,
  `app.use('/api/shift', require('./api/shift'))`). Исходников этого
  бэкенда в `kitchen-guide` нет — при реализации их нужно будет открыть
  прямо на сервере (или через другую сессию с доступом к нему).
- **Очередь печати + локальный агент на моноблоке** — уже есть и уже
  работает, это `oko-shelf-life-print` в этом репозитории
  (`kitchendesk.chefplan.ru`, ДРУГОЙ адрес/поддомен, не путать с
  `kitchen2026.chefplan.ru`) + `oko-shelf-life/agent/print-agent.js`.
  Агент уже умеет печатать произвольные строки текста (`job.printLines`)
  и QR-код (`job.qrData`) — это было сделано заранее, впрок, именно под
  эту будущую фичу. **Агента менять не потребуется вообще.**

Так что печать чек-листа связывает ДВА разных сервера: главный бэкенд
(`kitchen2026`, где живёт логика чек-листа и отправки отчёта) должен
попросить бэкенд `kitchendesk` (где уже есть очередь печати) напечатать
чек. Это межсерверный вызов backend → backend, не браузер → backend.

## Поток целиком, по шагам

1. Повар в приложении нажимает "🖨️ Печать" в экране "Чек-лист".
2. Фронтенд зовёт новый эндпоинт на `kitchen2026`: `POST /api/checklist/print`
   (авторизация — как у всех остальных вызовов, через Telegram `initData`,
   ничего нового придумывать не надо).
3. `kitchen2026`-бэкенд:
   - читает текущий чек-лист (цех + дата — как в `GET /api/checklist/:section/:date`)
     и текущие отметки выполнено/нет;
   - генерирует одноразовый токен завершения (случайная строка), сохраняет
     запись `{ token, section, date, telegramUserId, createdAt, expiresAt,
     used: false }` — нужно небольшое новое хранилище (таблица/файл,
     по аналогии с тем, как это сделано в `oko-inventory`/`oko-shelf-life`
     в этом репозитории — простой JSON-файл более чем достаточно, если в
     `kitchen2026` уже есть своя БД — тогда логичнее туда, по месту);
   - `expiresAt` — токен живёт 24 часа (та же логика, что уже
     использовалась для ссылки на пересчёт утвари — токен не бессрочный,
     чтобы старый распечатанный чек нельзя было отсканировать через месяц);
   - собирает `printLines` (см. "Что печатается" ниже) и `qrData` —
     ссылку вида `https://kitchen2026.chefplan.ru/shift/finish-by-qr/<token>`;
   - делает HTTP-запрос на `kitchendesk.chefplan.ru` (модуль
     `oko-shelf-life-print` в этом репозитории), создавая печатное задание
     с этими `printLines`/`qrData` — см. "Что нужно добавить в
     `kitchen-guide`" ниже;
   - отвечает фронтенду `{ ok: true }`.
4. Локальный агент на моноблоке (уже работает, без изменений) забирает
   задание из очереди и печатает — ровно так же, как сейчас печатаются
   этикетки разморозки/заморозки.
5. Повар физически отмечает пункты на бумаге (или просто использует её как
   памятку/бумажный след) и в конце сканирует QR камерой телефона.
6. Открывается страница `https://kitchen2026.chefplan.ru/shift/finish-by-qr/<token>`
   (обычная HTML-страница, без логина — токен сам по себе достаточен,
   такой же подход к доступу уже используется в `oko-inventory` для
   публичной страницы повара и в `oko-shelf-life` для страницы печати
   этикеток: "не разрекламировано, но не за паролем").
7. `kitchen2026`-бэкенд на этой странице:
   - проверяет токен (есть, не просрочен, не использован ранее — если
     уже использован, показывает "Эта смена уже завершена", не шлёт отчёт
     повторно);
   - помечает токен использованным;
   - вызывает **ту же самую** внутреннюю функцию, что и обычная кнопка
     "Завершить смену" (`POST /api/shift/finish`) — то есть логику
     завершения смены и отправки отчёта в Telegram НЕ дублируем, второй
     раз не пишем, дёргаем существующую функцию напрямую (с `note`, скорее
     всего пустым — на бумаге его не оставить, разве что решим иначе);
   - отдаёт простую мобильную HTML-страницу: "✅ Смена завершена, отчёт
     отправлен" (или "Уже завершена" при повторном скане).

## Что печатается на бумаге

```
KitchenDesk
------------------------------
Чек-лист смены
<Цех>, <дата>
------------------------------
[x] <позиция 1>
[ ] <позиция 2>
[x] <позиция 3>
...
------------------------------
Выполнено: <N> / <всего>
------------------------------
(QR-код)
Скан = завершить смену
------------------------------
```

`[x]`/`[ ]` — отметка того, что уже отмечено в приложении на момент
печати (не пустые чекбоксы под ручную отметку на бумаге — печатаем
снимок текущего состояния, как чек/квитанцию, а не бланк для
заполнения). Если понадобится другое поведение — печатать пустыми
для ручной отметки на бумаге — это отдельное решение, пока не выбрано,
надо будет уточнить у пользователя отдельно, если понадобится.

## Что нужно добавить в `kitchen-guide` (эта часть — реализуема прямо здесь)

Сейчас `oko-shelf-life-print` создаёт печатные задания только сам, изнутри
(`createPrintJob({ itemId, action, by })` — специфично для этикеток
разморозки/заморозки). Нужен **отдельный, более общий способ** поставить
задание в ту же очередь — произвольные `printLines` + `qrData` — чтобы
`kitchen2026`-бэкенд мог напрямую попросить "напечатай вот это", не
притворяясь этикеткой продукта.

Предлагается:
- новая функция в `oko-shelf-life-store.js`: `createRawPrintJob({
  printLines, qrData })` — просто кладёт задание в ту же очередь
  (`oko-shelf-life-print-jobs.json`), без всякой связи с позициями
  справочника;
- новый эндпоинт в `oko-shelf-life-api.js`, например `POST
  /api/oko-shelf-life-print/jobs/raw` — принимает `{ printLines, qrData }`,
  защищён **новым** секретом (не тем же `OKO_SHELF_LIFE_AGENT_TOKEN`, что
  у агента — тот даёт агенту право ЗАБИРАТЬ задания, а этот новый нужен
  для права СОЗДАВАТЬ произвольные задания извне; разные права разным
  сторонам, как и раньше в этом проекте). Условно —
  `OKO_PRINT_INTERNAL_TOKEN`, известен только серверам, которые имеют
  право печатать (пока что только `kitchen2026`), заголовок
  `X-Internal-Token`;
- агент (`print-agent.js`) трогать не нужно вообще — он уже полностью
  общий, просто печатает `job.printLines`/`job.qrData` независимо от того,
  откуда взялось задание.

## Что нужно добавить в `kitchen2026` (бэкенд + фронтенд — не в этом репозитории)

- Фронтенд: кнопка "🖨️ Печать" в `Checklist.tsx`, вызов
  `checklistApi.print()` → `POST /api/checklist/print` (новый метод в
  `services/api.ts`, по аналогии с уже существующими).
- Бэкенд: новый роут `POST /api/checklist/print` (собирает printLines +
  токен, зовёт `kitchendesk.chefplan.ru` — см. выше), новое хранилище
  токенов завершения, новый роут `GET /shift/finish-by-qr/:token`
  (публичный, без Telegram-авторизации — проверка по самому токену).
  Использует существующую функцию отправки отчёта, не копирует её код.
- Новая переменная окружения `OKO_PRINT_INTERNAL_TOKEN` (тот же секрет,
  что и в `kitchen-guide` — общий между двумя серверами) и адрес
  `KITCHENDESK_PRINT_URL=https://kitchendesk.chefplan.ru`.

## Открытые вопросы (не решены, требуют отдельного уточнения при реализации)

- Печатать снимок текущего состояния (как описано выше) или пустой бланк
  для ручной отметки на бумаге? Сейчас выбран первый вариант, но не
  проговорено окончательно.
- Что показывать в поле "заметка" отчёта, если смену завершили сканом QR,
  а не кнопкой в приложении, — оставить пустым, или дать возможность
  вписать заметку на следующем экране после скана?
- Как именно повар получает адрес телефона: TP QR ведёт напрямую на
  публичную HTML-страницу — не нужно ли предусмотреть отдельную явную
  плашку "если долго грузится — проверьте интернет" (моноблок и телефон
  повара не обязательно в одной сети, а сама страница — в облаке).
