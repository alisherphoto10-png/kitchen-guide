# Стекло нижней навигации — инструкция по интеграции

Нижняя навигация KitchenDesk (Главная/ТТК/Смена/План/Акты/Склад/Профиль) —
прозрачное зелёное стекло со скользящим индикатором активной вкладки, и
«Склад» раскрывает дугой вверх две такие же стеклянные плитки — Закуп и
Списание — вместо прямого перехода.

Согласовано по цепочке прототипов (каждый следующий уточнял предыдущий):
1. https://claude.ai/code/artifact/a22fb092-747e-43c3-aa7f-22e09767e728 —
   форма веера для «Склад» (вариант A: скруглённый квадрат вместо круга)
2. https://claude.ai/code/artifact/51c4e698-8b33-4973-a304-76bca691e1e0 —
   финал: прозрачное зелёное стекло на всей ленте и на плитках «Склад» —
   один и тот же рецепт, а не два разных стиля

Это временная папка-склад в репозитории `kitchen-guide` — код попал сюда
только для передачи на сервер, как остальные `oko-*` модули. После
интеграции можно удалить.

## Структура

```
frontend/
  BottomNav.tsx   — всё в одном файле: вся нижняя навигация, кнопка
                     «Склад» с веером, и стили стекла (через <style> внутри
                     компонента, без отдельного .css) — специально одним
                     файлом, чтобы просто скопировать и вставить целиком
```

## Почему CSS внутри компонента, а не Tailwind-утилиты

Остальной код KitchenDesk (видно по `oko-iiko-integration/frontend/`) —
React + TypeScript + Tailwind + `lucide-react`. Сам эффект стекла
(многослойный градиент + `backdrop-filter` + рамка + тень одновременно)
как набор Tailwind-утилит в JSX читался бы хуже, чем именованные классы —
поэтому CSS вынесен в строку `GLASS_NAV_CSS` и рендерится один раз через
`<style>{GLASS_NAV_CSS}</style>` в самом компоненте. Отдельный `.css`-файл
не нужен, импортировать ничего не надо.

## Как встроить

1. Скопировать `frontend/BottomNav.tsx` в папку компонентов реального
   фронтенда KitchenDesk (рядом, например, с `oko-iiko-integration`-компонентами).
2. Найти место, где сейчас рендерится нижняя навигация, и заменить его на:
   ```tsx
   import { BottomNav, type NavTab } from './BottomNav'

   <BottomNav
     active={текущийРаздел as NavTab}   // 'main' | 'ttk' | 'smena' | 'plan' | 'akty' | 'sklad-zakup' | 'sklad-spisanie' | 'profile'
     onNavigate={(tab) => /* существующая навигация — setState/navigate() */}
   />
   ```
   Компонент управляемый — какой раздел активен и что делать при переходе
   решает вызывающий код.
3. Если в проекте есть `useTelegram()` с `haptic` (как в `IikoCard.tsx`) —
   раскомментировать импорт вверху файла и добавить `haptic.impact('light')`
   на открытие/закрытие веера «Склад» и на выбор плитки.
4. `#34c17a` внутри `GLASS_NAV_CSS` (`.kd-glass-indicator`) — это акцент
   KitchenDesk; если в проекте есть переменная темы для него, подставить
   её вместо литерала.
5. Расстояние разлёта плиток «Склад» (58px по горизонтали, 20px вверх)
   подобрано под квадрат 50px — если реальная ширина кнопки в ряду заметно
   другая, поправить `calc(-50% ± 58px)` внутри `GLASS_NAV_CSS` на глаз.

## Проверено перед передачей

Так как реальный файл нижней навигации не в этом репозитории (KitchenDesk
не под git — правки вносятся на сервере), собрать точный diff нельзя. Зато
сам файл проверен по-настоящему, не только на глаз:
- **Типы:** `tsc --noEmit` проходит без ошибок.
- **Рантайм:** собрал `BottomNav.tsx` через esbuild с реальными `react` и
  `lucide-react`, отрендерил в браузере, прокликал все вкладки — индикатор
  корректно скользит и меняет ширину под каждую кнопку; открыл веер
  «Склад» — плитки раскрываются, выбор «Закуп»/«Списание» закрывает веер и
  переводит активную вкладку, индикатор доезжает до «Склад».
- **Баг найден и исправлен на этом шаге:** пока веер открыт, но выбор ещё
  не сделан, подпись «Склад» готовилась под тёмный текст (как будто под
  ней уже есть зелёная пилюля) — на самом деле пилюли там ещё нет, текст
  был почти нечитаем на стекле. Добавлено отдельное светлое
  превью-состояние (`is-open`) для этого момента — тёмный текст
  (`is-active`) появляется только когда раздел реально открыт.
