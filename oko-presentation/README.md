# OKO / KitchenDesk — скриншоты для презентации (для потенциальных клиентов)

Временная папка-склад (как `oko-order-relay/` и `oko-iiko-integration/`) —
сюда нужны **реальные скриншоты** реальных экранов приложения. Я (сессия
Claude Code on the web) не могу сама зайти на `kitchendesk.chefplan.ru` —
сеть, в которой я работаю, блокирует выход на этот хост политикой (не логин/
пароль, а сетевой уровень). GitHub мне доступен нормально — план: сервер
делает скриншоты и коммитит их сюда, я собираю из них интерактивный веб-тур.

**Важно про аудиторию:** это не внутренняя техническая документация — это
презентация для потенциальных клиентов/ресторанов, которые решают,
подключаться ли к KitchenDesk. То есть нужен **полный обзор приложения**, не
только iiko-часть (она — один из разделов, не вся презентация), и снимать
стоит в состоянии, которое выглядит убедительно (заполненные реальными
данными экраны, не пустые списки) — раз ресторан 6 уже наполнен тестовыми
данными (10 сотрудников, несколько ТТК с категориями), показывать лучше на
нём.

## Что автоматически не снять — нужны твои реальные скриншоты

Сообщения самого бота внутри Telegram — интерфейс Telegram-клиента, не
веб-страница, скриншотить нечем на сервере. Эти несколько экранов лучше снять
вручную с телефона и прислать в чат отдельно (не через эту папку):

- Сообщение с заказом в поварской группе (после отправки формы).
- Кнопка «✅ Принято» до нажатия.
- Как выглядит сообщение после нажатия «Принято» (кто принял, с тегом повара).
- Подтверждение в исходном топике (цитата заказа).

## Формат

- PNG, не сжимать агрессивно (нужно читаемо, не мыльно), но и не оставлять
  совсем сырые огромные файлы — среднее качество достаточно.
- Снимать в состоянии с реальными заполненными данными, не пустые экраны —
  это презентация для клиентов, должно выглядеть убедительно.
- Если что-то не получается снять или раздел ещё пустой (например, отчёты по
  продажам, которые на demo iiko всё ещё нулевые) — пропустить, указать в
  отчёте, что и почему, не выдумывать данные ради красивой картинки.
